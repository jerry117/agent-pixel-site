# Agent 像素工地

在会话输入框上方（`conversation.input.dock` 槽位）渲染一块像素风工地横幅，把本会话的 Agent 画成工地上的小工人：

- **工头** —— 当前会话自己的 Agent。它的状态由会话日志折叠而来：
  - 读文件（read / grep / glob / web 检索等）→ 走到**档案室**翻资料；
  - 写代码（write / edit / apply_patch）→ **砌墙盖房**；
  - 工具执行失败 → 房子**冒烟**（烟囱飘烟动画）；
  - `approval/asked`（等待权限审批）或 `ask_user_question`（向用户提问）→ **举牌**；
  - 回合开始 / 结束 → 看图纸 / 喝茶待命。
- **小工人** —— 每个登记在案的 subagent（`subagent/catalog`）都会带着帐篷（一次性）或小屋（可续接）入驻；被 `subagent` / `spawn_teammate` 派工时开工砌墙，结果返回后收工（失败则冒烟）。
- **workflow 成员** —— `tool-workflow/*` 事件让每个成员以蓝图小屋入驻，按结局收工或冒烟。
- **任务牌** —— 左侧木牌显示 `todo_write` 的最新清单（绿=完成、黄=进行中），房子屋顶随完成比例逐层搭起，全部完成时插旗。

## 数据来源与边界

状态完全由**当前打开会话的日志**折叠为一个 `pixelSite` 会话投影（Host 侧纯函数折叠，经 `wire.view` 下发，客户端只渲染）。因此：

- 工人的细粒度动作（去档案室 / 砌墙 / 举牌）来自会话自身的工具调用与审批审计事件；
- subagent / workflow 工人展示的是父会话日志里的**派工与结算里程碑**，不含子会话内部的逐工具动作；
- 投影与日志同源，重放、fork、恢复后结果一致。

已打开会话且槽位提供必要接口时，空投影也显示待命工地；缺少 useProjection 或翻译接口时隐藏。

## 实现约束（维护必读，均为实战踩坑）

- **禁止变量遮蔽 `h`**：`h` 是 `React.createElement` 的别名。像素子组件（`R`、`PixelSvg`）的高度参数曾命名 `h`，函数体内 `h('rect'/'svg',…)` 调到的是**数字**，子组件渲染阶段必然 TypeError → 错误边界**永久弃位**（条目静默消失、无可见报错）。高度一律命名 `height`。回归防护：`node render-check.mjs`（346 次组件调用的递归渲染校验）。
- **入口组件必须容忍 `props === undefined`**：渲染器装配期会用无 props 调用组件（本部署观测到 6 次）。第一行解构需 `props ?? {}`，无 props 时返回 null。
- **客户端组件不得使用 react 模块表里的 Hook**（`React.useEffect`/`useState` 等）：本部署中模块表提供的 React 与页面渲染实例未配对，调用会抛 React #321，被槽位错误边界捕获后条目**静默弃位**。数据订阅只能用运行时下发的 Hook props（`useProjection`）。
- 渲染失败时组件返回 `null`（隐藏而非崩溃），这是刻意的降级策略。
- 折叠状态机改动需同步递增 `STATE_VERSION` 并更新单测。
- 排障经验：槽位条目「静默不可见」时，用渲染期 `fetch` 到本地监听端口做信标（无 Hook、先于崩溃派发），比读控制台可靠。

## 验证

- 已验证：bundle 安装、Host 投影注册、Client 槽位注册、页面加载与模块激活（含桌面 Electron 页面）、`useProjection` 数据流、会话日志驱动（工具调用、审批、subagent 目录、workflow、todo 事件）、21 项折叠单测。
- 未验证（需现场观察）：像素画在浅色/深色主题下的观感、多工人横向滚动。
